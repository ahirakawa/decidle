## 報告の出し方

報告を求められた作業を終えたら、報告を JSON のファイルに書く。人間はその JSON から作られるページを読む。ターミナルの返事は読まれない前提で、短くする。

1. 報告を `<作業ディレクトリ>/.decidle/<作業名>.report.json` に Write で書く。作業名は英数字とハイフンで付ける。同じ作業の続きなら、同じファイルを上書きする。
2. ターミナルの返事は 400 字以内にする。書くのは、結論と、決めてほしいことの有無だけ。

JSON の形は次のとおり。キーは全部必須で、該当がない配列は `[]` にする。

```json
{
  "title": "作業の名前",
  "goal": "人がこの作業で何をしようとしていたかを 1 文で",
  "conclusion": "何が起きたか、何を変えたか。200 字以内。内訳や経過は書かない。",
  "decisions": [
    {
      "question": "何を決めてほしいかを 1 文で。40 字以内",
      "options": [
        { "label": "選択肢の名前", "effect": "これを選ぶと何が起きるか" },
        { "label": "もう 1 つの選択肢", "effect": "これを選ぶと何が起きるか" }
      ],
      "recommend": "勧める選択肢の label と同じ文字列",
      "reason": "勧める理由"
    }
  ],
  "verified": ["実際に実行して確かめたこと"],
  "unverified": ["確かめていないこと、確かめられなかったこと"],
  "deliverables": [
    { "path": "docs/plan.md", "summary": "何を書いたか、何を変えたかを 1 文で" },
    { "path": "content/items/", "summary": "同じフォルダのファイルが多いときは、フォルダの path と件数で書いてよい" },
    {
      "path": "src/auth/client.ts",
      "summary": "コードのファイルは、ファイルごとに項目を作り、changes を 1 か所以上書く",
      "changes": [
        { "line": 42, "before": "どう動いていたか。新しいファイルは「なし（新規）」", "after": "どう動くか" }
      ]
    }
  ]
}
```

書くときの決まりは次のとおり。

- このターンで編集したファイルは、全部 deliverables に入れる。
- goal には、作業の中身ではなく、人がこの作業で何をしようとしていたか(目的)を書く。
- decisions には、人間にしか決められないことだけを書く。自分で決めたことは conclusion か verified に書く。
- question は Home のカードに出るので 40 字以内にする。背景や理由は reason か options の effect に書く。
- verified には、このターンで実際にコマンドを実行して確かめたことだけを書く。
- 作業の途中で付けた呼び名や番号は、使うたびに中身を言い直す。
- 分野や方針の名前だけで済ませず、実際に何をするのか、何が変わるのかを書く。
